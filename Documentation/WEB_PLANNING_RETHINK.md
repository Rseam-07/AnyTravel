# Web 路线规划重做说明

更新：2026-09-28。范围为 Web 路线与交互、配套查询后端；发布入口为 https://rseam-07.github.io/AnyTravel/ 。本次数据源实测与边界见 [网页发布检查](WEB_RELEASE_20260928.md)，不代表 iOS、Android 或第三方下单完成验收。

## 规划要解决的问题

输入攻略里的景点名单，再按热度和每天几个点分组，会产生三个问题：没有考虑首末日实际能用的时间；移动、用餐和休息挤掉游览；一次小调整让整趟旅行重新洗牌。

这版将攻略用作地点信息与经验的来源。攻略的“必去”只提供较小的推荐权重，用户明确选择的“必去”优先级最高。“适合傍晚”是偏好，不当成下午禁止游览的开放规则。未知开放时间明确标为待核实。

## 现在怎样安排

1. 按出发日期和旅行天数建立每天的时间窗口，首日开始时间和末日结束时间进一步收窄窗口。铺松行程不会偷偷增加天数。
2. 去重、检查坐标，按地点名称和地理位置匹配资料，避免套用其他城市同名地点的停留信息。同位置、同场馆名的城市/中国冠名别名合并；必去与锁定的标识保留，不会将独立展馆仅凭距离合并。
3. 先保留锁定的日期与时段，再逐次评估“候选地点插入某天某个位置”是否可行。完整停留、移动、餐休、等候和机动时间共同参与判断。
4. 可行候选之间，比较个人偏好、新增路程、同类体验重复和等待；长距离跨区、连续同类地点的收益降低。不会因为还有候选，就必须全部放进去。
5. 整日景区保留足够时间；儿童、长辈和行动需要增加休息。午餐可以接在上午游览之后，开放或锁定时段前的等待也能容纳午餐，减少空等。
6. 没放进去的地点进入备选，说明原因；必去地点放不下时显示冲突。用户可以直接替换一站、移除一站、锁定时段或撤销。

生成、局部替换、移除、日期调整与路段耗时更新使用同一个 `scheduleDay`，避免页面与规划器各算一套时钟。局部替换和移除只重算当天。路段服务返回更长耗时后会重新核算并标出冲突，保留用户已经选择的地点。

这是一套可解释的约束与增量插入启发式算法，不承诺数学意义上的全局最优。容量上限和节奏参数属于产品假设，可以继续根据真实旅行反馈调整。

## 页面与动效

保留 AnyTravel 的地图主视图、青绿色和玻璃面板。条件填写围绕“可用时间 → 节奏和移动 → 必去/不去”展开，同行、预算与往返信息可按需展开。生成后直接显示每天的时间构成、停留顺序和备选。

使用用户提供的 [motion-web](https://github.com/feitangyuan/motion-web)，阅读版本为 `5f4e40f1253e11e28850d08dce28b9b7e4320115`。采用其产品控件状态、运动连续性与实际交互验证方法：

- 日期、节奏和内容切换的指示块使用可被打断的弹簧，保留位置与速度；刚度 350、阻尼 28，分步积分。
- 按钮有按下反馈，路线条目短距离入场；动画不阻碍点击或键盘操作。
- 减少动态效果时直接落到目标状态，地图镜头同样关闭过渡。
- 同时检查错误、空态、禁用、锁定、深色、窄屏和地图不可用状态。
- 地图视野避开桌面面板与手机底部面板，单个地点也在可见区域内；切换日期不再被第二次“飞回市中心”覆盖。

## 数据边界

- 攻略快照不是当日营业或预约确认。只对能解析的明确日期/时段约束进行检查；节假日例外、预约场次、停止入场时间仍需另外核实。当前知识库没有系统覆盖逐日开放规则。
- 市内公交耗时和无法取得路由的路段使用距离、绕行与接驳估算。步行/驾车路由可用时接回同一时间表，但也不是实时路况。
- 每天的初始位置仍为城市中心，未自动接入真实酒店、车站到达时间；表单明确要求用户为抵达、安顿与返程接驳留时间。交通预选会核对首末日时间，并按火车 1 小时、飞机抵达后 2 小时/出发前 3 小时作保守接驳预留；冲突班次显示提示，不静默改写用户的日程。
- 地图虚线是访问顺序示意，不声称沿道路通行。未知票价不会用虚构数字补齐，预算尚不是景点选择的硬约束。
- 地点发现仍沿用已有本地地点包、知识库与在线检索，不以增加攻略数量代替路线质量。候选点的覆盖、坐标和停留建议仍会影响结果。

## 验证与复现

- `npm --prefix Web test -- --reporter=dot`：包括首末日半天、必去但不可行、明确闭馆、跨午休开放时段、未知开放、饭点与等待、整日景区、步行远距、同行休息、锁定、真实路段重算，以及已有的种子随机城市回归。
- `npm --prefix Web run build`：TypeScript 与 Vite 生产构建。
- `Web/scripts/check-planner-ui.cjs`：使用 Playwright 和已安装的 Chrome，验证实际按钮、替换/移除对其他日期的保持、锁定与撤销、键盘、弹簧中间帧、减少动态、深色、窄屏、在线服务失败与无 JavaScript 提示。默认连接 `http://127.0.0.1:5190`，可通过 `PLANNER_QA_URL` 修改；`PLAYWRIGHT_MODULE` 可指定已有 Playwright 模块路径。
- 浏览器记录和截图输出在 `output/planner-rethink/`。这些是本地浏览器验证，不等同于真实手机或全站发布验收。

本轮结果：16 个 Web 测试文件、118 项测试通过；后端 76 项测试通过；TypeScript、生产构建和知识库校验通过。浏览器验证覆盖 320、375、390、414、768、1440 像素宽度。替换、移除、锁定时段、撤销、键盘、减少动态、深色文字、单点地图可见性及在线服务不可用时的本地规划均通过实际页面操作验证。追加验证了资料导入、完整手册备份、账本、打印、实付金额小数与生产构建断网恢复。

构建仍提示较大的代码分包：主包约 801 kB（gzip 199 kB），地图相关共享包约 1.06 MB（gzip 286 kB）。地图已延迟加载；未做中端 Android 真机或慢速网络性能验收。
