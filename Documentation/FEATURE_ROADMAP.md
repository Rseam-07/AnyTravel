# AnyTravel 功能路线图

> 旅行不是把地点塞进表格，而是让时间、预算、住处与抵达方式在地图上彼此照亮。

这份清单以“用户能否完成一次真实任务”为验收标准。只有入口、静态卡片或演示数据不会标为完成；联网数据必须显示来源、抓取时间和失败状态。参考应用的条目来自静态资源与模块结构，只用于功能盘点，后续仍需逐条走查验证。

## 已经可以使用

| 旅程环节 | 当前能力 | 验收边界 |
| --- | --- | --- |
| 初次进入 | 四页欢迎与初始化设置；保存出发地、人数、预算；默认松弛节奏 | 可重新进入设置，减少动态效果时自动简化动画 |
| 地图规划 | 地图为全屏背景，地点、住宿、车站和每日路线随卡片选择联动 | 用户拖动地图后停止自动抢镜；点卡片可重新聚焦 |
| 自由输入 | 目的地、日期/天数、预算、兴趣、节奏、住宿和交通可任意顺序填写或跳过 | 缺少非关键字段仍可继续，必要信息会在生成前明确提示 |
| 景点与路线 | 真实地点搜索、逐日分组、距离与预计时间；iOS 使用逐路段路径，Android 0.4 使用游览顺序连线 | Android 会明确标注路线为示意，不把连线冒充道路导航 |
| 方案编辑 | iOS 可在生成后搜索并添加真实地点、拖动排序、删除停靠；可另行修改日期、出发地、预算、人数与交通偏好 | 每天至少保留一处；路线变化后重新绘路并使住宿、接驳与报价进入待复核状态 |
| 住宿 | 酒店/民宿候选、景点均距、枢纽距离、选择后重排交通 | RollingGo 与已登录携程会话可返回实时报价；其他渠道保留明确查询入口 |
| 大交通 | 铁路去程/返程独立班次、席别、余票、价格、选择与购买入口；航班/客运模型与渠道入口 | 单边查询失败不会遮住另一边；实时价、参考价和待查询状态分开展示 |
| 门到门接驳 | iOS 分别比较去程枢纽→住宿、住宿→返程枢纽的公交、打车与步行，并联动地图和费用 | 真实 MapKit 路线与距离估算分开标注；估算公交不会冒充已取得路线 |
| 完整方案 | 每日时间表、地点介绍、住宿、交通、路线和费用明细 | 默认每天两处主要停留，并留出午餐、休息与机动时间 |
| 方案导出 | iOS 原生生成带地图的多页 PDF 与可导入日历的 `.ics`，并通过系统分享页交付 | 没有日期仍可导出 PDF；日历必须先补日期；地图失败时保留文字方案并明确说明 |
| 行程保存 | 本地保存、查看、恢复与删除；iOS 恢复后自动复核路线、住宿与报价 | 重启应用后仍可恢复，旧价格不会被无提示地当作新报价 |
| 平台会话 | iOS 支持携程、去哪儿、同程、Trip.com、12306 的应用内网页登录；Android 0.4 提供平台入口 | iOS 以有效平台 Cookie 校验会话状态；密码只交给平台网页；Android 会话复用仍待实现 |
| 智能向导 | iOS 支持伴随服务托管 GLM 与用户自定义 OpenAI 兼容模型；可控制节奏、交通、预算和现有地点焦点 | 服务端 Key 不进入 App；自定义 Key 只进钥匙串；所有地图动作均经本地白名单复核 |

## 不会用“完成”掩盖的边界

- 静态资源中的功能名称不能证明参考应用的全部行为，深入走查会后续补做。
- 聚合页展示的数字只有在酒店、日期、房型与价格口径匹配后才会标为实时价。
- 平台登录状态不等于已经获得可用接口；失败时仍保留其他渠道和官方购买页。
- 模拟器通过不等于真机、弱网和长期会话通过；每个版本都会单独写明验证范围。
